02

Deadlock Conditions

Meaning, examples, and prevention strategies for the four necessary conditions of deadlock.

1

Mutual Exclusion

Meaning:

A resource can be used by only one process at a time. If another process requests the same resource, it must wait until the resource becomes available.

Example:

A printer generally handles one printing job at a time.

Prevention Strategy:

Mutual exclusion can be removed only when a resource can safely be made shareable. However, some resources—especially certain hardware devices such as a printer executing a print job—are inherently non-shareable. Making these resources shareable may require changes to their hardware design or operating mechanism, which is not always technically feasible. Therefore, mutual exclusion cannot be eliminated for every resource in practice.

2

Hold-and-Wait

Meaning:

Hold-and-wait occurs when a process holds one or more resources while waiting for additional resources held by other processes.

Example:

Process P1 holds a printer and waits for a scanner that is currently held by another process.

Prevention Strategy:

Require processes to request all necessary resources before execution or release currently held resources before requesting additional ones. A waiting-time limit can also be used as an additional policy, requiring a process to release its resources and exit or restart if its waiting limit is exceeded.

3

No Preemption

Meaning:

No preemption means that a resource cannot normally be forcibly taken away from a process. The process must release the resource voluntarily after completing its work.

Example:

A process holds a resource while waiting for another resource, and the operating system cannot reclaim the held resource under the current rules.

Prevention Strategy:

Permit resource preemption under suitable conditions. If a process cannot obtain a requested resource, it may be required to release its held resources and retry later. This approach is suitable only when the resource state can be safely preserved or restored.

4

Circular Wait

Meaning:

Circular wait occurs when a group of processes forms a circular chain in which each process waits for a resource held by the next process.

Example:

P1 waits for a resource held by P2, P2 waits for a resource held by P3, and P3 waits for a resource held by P1.

Prevention Strategy:

Assign a fixed ordering to resource types and require processes to request resources according to that order. This prevents circular resource dependencies.

Deadlock Theory & Prevention Strategies

The four necessary conditions for deadlock and the strategy used to prevent each one.

A deadlock occurs when two or more processes wait indefinitely for resources held by one another. Deadlock prevention aims to ensure that at least one of the four necessary conditions cannot hold, so the system avoids entering a deadlock state.
CONDITION 01

Mutual Exclusion

What it is: A resource can be used by only one process at a time. Other processes requesting that resource must wait until it becomes available.

Example: A printer generally handles one printing job at a time.

Prevention strategy: Make resources shareable wherever possible. However, mutual exclusion cannot be removed for inherently non-shareable resources, such as a printer performing a particular job, so this condition cannot always be eliminated in practice.

CONDITION 02

Hold-and-Wait

What it is: A process holds one or more resources while waiting to acquire additional resources that are held by other processes.

Example: P1 holds a printer and waits for a scanner currently held by another process.

Prevention strategy: Require a process to request all needed resources before it begins, or make it release held resources before requesting more. A system may also apply a waiting-time limit and require a process to release resources and exit or restart if that limit is exceeded.

CONDITION 03

No Preemption

What it is: Resources cannot normally be forcibly taken from a process; the process releases them voluntarily after finishing its work.

Example: A process keeps a resource while waiting for another resource, and the current rules do not allow the held resource to be reclaimed.

Prevention strategy: Allow safe preemption when appropriate. If a process cannot obtain a requested resource, it may need to release its held resources and retry later. This works only when the resource state can be safely preserved or restored.

CONDITION 04

Circular Wait

What it is: Processes form a circular chain where each process waits for a resource held by the next process.

Example: P1 waits for a resource held by P2, while P2 waits for a resource held by P1.

Prevention strategy: Assign a fixed ordering to resource types and require processes to request resources according to that order. This prevents circular resource dependencies.
